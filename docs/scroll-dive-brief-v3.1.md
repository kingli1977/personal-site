# 返修单 v3.1：性能修正（只降计算成本，不动视觉）

背景：v3.0 海面观感通过，但实测卡顿。根因二：①移植时照抄 TDM 上游默认 NUM_STEPS=32，而 gyut.cn 原作实测用 9 步（细节由法线采样补足，视觉无损）——我们的海面段成本是原作的 ~2.5 倍；②main.js adaptScale 自适应存在振荡：下调一次降 18%，上调每窗只升 6%，边界机器会反复触发 resize 造成顿挫。

## 1. frag.glsl：求交降配（对齐 gyut.cn）
- `const int NUM_STEPS = 32` → `10`
- ITER_GEOMETRY=3、ITER_FRAGMENT=5 保持不变（法线细节的来源，不动）
- 不得改动 getSeaColor/getNormal/getSkyColor 任何参数（视觉不回退的保证）

## 2. main.js：adaptScale 防振荡
- 改为离散档位：1.0 / 0.85 / 0.7 / 0.55，只允许逐档移动
- 每次变档后 2.5 秒冷却期内禁止再变档
- 上调条件从 avg<18 收紧为 avg<15（更确凿才升档）

## 3. 验收（不得回退项）
- 0.02 中带 hgrad ≥ 2.0；0.45 p99≤70/R/B≤0.22；0.90 p99≤60/R/B≤0.22；顶带 R/B≤0.7
- Chrome ≥50fps @1512×858
- 汇报：改动 diff + 自检数值 + 预览链接，禁自评
